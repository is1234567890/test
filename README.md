# ＜カプセル化＞
個人情報を考えたとき、名前は病院、役場、学校、職場など様々な局面で公開することがある
このような情報をpublicな情報とする。
publicな情報とは誰でも知りえる情報で全体に公開されている情報である。

次に自宅住所は限られた人のみに公開される情報である。
このような情報をprotectedな情報とする。
protectedな情報は誰にでも見られていいわけではなく公開範囲に制限がかかった情報である。

最後に預金残高は本人以外知られてはいけない情報である。
このような情報をprivateな情報とする。

上記のように個人情報には公開範囲の制限の違いがあり、これをオブジェクト指向の話に落とし込むと
〇publicな情報
〇protectedな情報
〇privateな情報
（これ以外にもプログラムでは情報の制限を掛けられる。　ソースを書く中でその点について学ぶと分かりやすい）
上記のような分類ができる。
これをカプセル化と呼ぶ。

# ＜継承＞
継承を説明するに当たって、こんな話をするとイメージしやすいだろうか。

陶芸家とその弟子
陶芸家は弟子に器の作り方を教える
土の捏ね方や、ろくろの使い方、そして焼き方など
弟子はそれらを覚え、陶芸家の先生の技術を自分のものにしていく
これを技術の継承という

オブジェクト指向の世界でも同様に継承の考え方があり、Aが持っているものをBでも利用できる仕組みが提供されている。

# ＜ポリモーフィズム（多様性）＞
・オーバライド
継承により引き継いだ親メソッドについて子クラスではメソッドの振る舞いを独自に書き換えできる。
上記の陶芸家と弟子の話で考えると弟子が受け継いだ技術を自分なりにアレンジするイメージ。

・オーバーロード
同名のメソッドを引数の個数の違いで複数定義することができる。
これをオーバーロードという。
例えば、天候によって同じ陶器焼きの作業（同名のメソッドのイメージ）でも使う巻きの個数や着火剤（パラメータのイメージ）を使用したり、
工夫することがある。
